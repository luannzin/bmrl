# Breakthrough lab: structural shortcuts in Bitcoin proof of work

Question: does the structure of SHA256d over Bitcoin's 80-byte header allow
a target hit with fewer expected evaluations than exhaustive search?

**Answer from this run: no.** At 64 rounds every measurement matches the
random-function null, including statistics computed over *every one* of the
2^32 nonces of 16 templates (4 of them real mainnet blocks). No strategy in
any tested family lowers the held-out work per hit. Reduced-work algorithms
exist only at 4 rounds per compression, where H7 is affine in the nonce.
Measurable structure (cube sums, characteristics) exists only up to 5 rounds.
Grover search lowers the number of *queries* in a speculative model, but the
600 s block interval turns that back into near-linear total work, on an
infeasible number of machines.

Every record below is in `experiments/results/` and was produced by commit
`49a3e3c` in one clean run; `bmr research audit` passed on it. Each of the
twelve older experiment kinds gave a result digest identical to the
previous final run (`480c36f`). The nonce atlas gave the same digest in
three full executions: a preliminary run, the final run, and an in-process
rerun on 14 threads. The hypothesis board is [BOARD.md](../BOARD.md),
regenerated by `bmr research board`.

## Mission 1: the specialised mining function

**The exact function.** A template fixes block 1 of the header (version,
previous hash, the first 28 bytes of the merkle root), so the miner hashes
it once as a midstate. Per nonce, three compressions are cut down to two:

| Input | Where it enters | Varies how |
| --- | --- | --- |
| nonce | block 2, W3 = bswap(nonce), round 3 | free, 2^32 values |
| time | block 2, W1, round 1 | within about 2^13 s of the median past block |
| merkle root bytes 32..35 | block 2, W0, round 0 | only with the whole root, so the midstate changes too |
| bits, padding | block 2, W2, W4..W15 | constant |
| version (BIP320), extranonce | block 1 | new midstate |
| inner digest | outer block, W0..W7 | pseudo-random, not chosen; W8..W15 constant |

The target compares the 256-bit number whose top word is bswap(H7) of the
outer compression, and H7 = IV7 + e60 exactly.

Exact consequences (board B-11, B-12, B-16):
- The header encoding is injective, so input equivalence classes are
  trivial. Distinct (template, extranonce, time, version, nonce) values
  never repeat work. Equal outcomes would need an inner-digest collision,
  probability about 2^-256 per pair.
- Every effect of the fixed fields lowers the cost per hash and leaves the
  number of hashes unchanged: midstate, 3 precomputed rounds, constant
  W16 and W17, the early reject at round 60 (at most 3 of 125 rounds, 2.4%),
  and AsicBoost-style schedule sharing.

**Nonce-to-digest structure, exhaustively** [nonce-atlas-0002]. Every nonce
of 12 synthetic templates and of mainnet blocks 0, 1, 100000 and 125552
was evaluated at 64 rounds, plus 4 templates at each of 4, 5, 6 and 8
rounds. That is 1.4 × 10^11 SHA256d evaluations per execution, 2.7 × 10^11
with the in-process rerun. Each is recorded in an image bitmap, a
leading-zero histogram, a binary XOR tree over the nonce index and a hit
list. 58 tests ran at 64 rounds and none is significant
(Bonferroni over all 242 p-values, threshold 4.1e-5):

| Statistic at 64 rounds | Observed | Null |
| --- | --- | --- |
| Image size of nonce -> top word, 16 templates | z from -1.27 to +2.29 | (1 - 1/e) 2^32, sd 20,433 |
| Nonces with top word 0 (synthetic) | 14 | Poisson(12) |
| Leading-zero histogram, pooled | chi² p = 0.12 (33 df) | geometric |
| Full-cube and 31-dim cube sums, 135,168 bits | z = +1.30, no all-zero word | uniform |
| Sub-cube zero rates, dimension 8..32 | max abs(z) 1.71 | 1/2 |
| Per-bit zero rate at dimension 8, 256 bits | max abs(z) 3.0 (H7 bit 20) | 1/2 |
| Known mainnet nonces | all four found, with 43, 32, >= 64 and 46 zero bits | positive control |

**Input selection** (B-03, B-04). Each family's best strategy on six
discovery templates was measured once on ten held-out templates. Work per
hit is 1/A:

| Family (strategies scored) | Discovery winner | Held-out A (95% CI) |
| --- | --- | --- |
| Fixed 1 or 2 bits (2,048) | nonce bits 0,2 = 1,0 | 0.9990 (0.994..1.004) |
| Byte value (1,024) | byte 3 = 0x2c | 1.020 (0.982..1.060) |
| Hamming weight (testable classes) | weight 22 | 0.9956 (0.976..1.016) |
| Linear half-spaces (2^25 masks, Walsh-Hadamard) | parity(nonce & 0x00b476de) = 1 | 0.9973, held-out z = -2.2 (wrong direction) |
| Neighbours (1,552 relations + 3 groups) | x ^ 0x22 | 1.20 (0.55..2.62) |
| All 2^32 - 1 XOR / 2^31 modular differences among 2^14 hits per template | max multiplicity p = 0.62 | 0 held-out pairs (0.31 expected) |

So a usable fixed-bit strategy saves less than 0.4% (95%). No family's
held-out interval excludes A = 1.

**Positive controls.** At 4 rounds the same pipeline detects everything it
should. The map is a bijection (image 2^32 exactly, z = 77,327). Each
template has exactly one zero preimage. The leading-zero histogram is
*under*-dispersed (chi² p = 1.000), as a permutation's must be. The hit
set is an affine subspace: XOR neighbours of hits are hits 65,537× as
often (held-out). Sub-cube sums vanish (zero rate 0.709).

## Mission 2: automated cryptanalytic discovery

**Solver-optimal characteristics** [trail-sat-0001]. z3 minimised the
characteristic weight over every difference in the nonce, and separately
over every difference in nonce and time. The model is signed carry-free
sums with two-digit cancellation and free Ch/Maj choices. The solver chose
the differences itself; every round it returned was then measured on real
transitions:

| Rounds after the nonce enters | Optimal weight, nonce | Same, nonce + time | Measured (Markov product) |
| --- | --- | --- | --- |
| 1 (through round 3) | 0 | 0 | 2^0 |
| 2 (through round 4) | 11 | 11 | 2^-10.97 per round product; end to end 2^-11.007 on 2^28 header pairs |
| 3 (through round 5) | 38 | 38 | 2^-35.68 (nonce), 2^-35.53 (nonce + time) |
| 4 (through round 6) | >= 50 (budget) | >= 39 (budget) | - |

Time freedom does not help: every optimum puts its whole difference in
W3. The model is exact at 2 rounds and 2.3 to 2.5 bits pessimistic in the
last round at 3. Even so, a characteristic through round 5 is followed by
2^31 × 2^-35.5 ≈ 0.04 nonce pairs per template. The inner block still has
58 rounds to go after that, and the outer block 64. This proves (under the
solver model) and measures the earlier heuristic finding that header
trails stop at round 5.

**Exact identities** [trail-sat-0001]. z3 proves, for every template
(symbolic midstate and tail):

- H7_4(n) - bswap(n) is independent of n;
- H7_5(n) = K + bswap(n) + Σ1(X) + Ch(X, IV4, IV5), where X = C + mid0 + A5(n)
  and A5 is one inner round of n.

Both also hold on 4,096 random headers under an independent SHA-256, with
the 5-round formula re-derived in Rust.

**New reduced-round structure at 5 rounds** [nonce-atlas-0002]. Aligned
8-dimensional sub-cubes over the nonce's low byte make output bits 1 and 0
of H7 sum to zero too often: rate 0.5272 (z = 445) and 0.5038 (z = 63)
over 4 templates. The low nonce byte is the top byte of bswap(n). IV4 is
odd and IV5 even, so the identity gives H7_5 bit 0 = c ^ X0 ^ X6 ^ X11 ^ X25:
a low-degree function of carries in one round. No other bit is
significant. Neither is any strategy at 5 rounds: the deficiency shows
which bits have low degree; it does not raise the hit rate of single
nonces. At 6 and 8 rounds nothing at all remains (0 of 46 tests each).

**Linear, Boolean and conditional-probability structure.** The Walsh scan
is the exhaustive linear search over the nonce, every half-space of two
24-bit projections, and it finds nothing past 5 rounds. The class families
cover conditional hit probabilities, and the all-differences scan is a
model-free search over every nonce differential at the output level.

## Mission 3: reduced-work algorithms

Every candidate, with its algorithm, assumption, expected work and status:

| Algorithm | Assumption | Expected work per hit vs exhaustive | Status |
| --- | --- | --- | --- |
| Hash only nonces in the best fixed-bit / byte / weight class | class chosen on other templates | 1/A_held = 1.001, 0.980, 1.004; CIs include 1 | refuted at 64 rounds |
| Hash only a linear half-space | mask chosen on other templates | 1.003 | refuted |
| Hash neighbours of share hits | relation chosen on other templates; trail-search measures share-to-target | atlas CI includes 1; trail-search 0.9997 | refuted |
| Filter by trail conditions | 11 exact conditions | about 81 (filter costs more than it keeps) | refuted (trail-search) |
| Abort before round 60 | target bits = IV7 + e60 | impossible; the round-60 abort is already in the kernels (cost per hash) | exact |
| Solve the target with SAT/SMT | QF_BV, nonce symbolic | slower than brute force from 8 rounds; 16 rounds time out | refuted beyond 4 rounds |
| Invert the 4-round affine map | 4 rounds only | 0.045 (trail-search), exact inverse by z3 | reduced-round only |
| Grover with a reversible oracle | speculative hardware | queries (π/4) 2^(d/2) serially; with a 600 s deadline, 4.8e-5 × classical evaluations over 4.5e15 machines at d = 80 and 1 µs per Toffoli | model only |

None is a reduced-work algorithm for 64-round SHA256d. A faster
implementation of the same number of hashes (the planned GPU kernel v2,
AsicBoost, early reject) is cost per hash, never fewer hashes.

## Mission 4: hypothesis evolution

`bmr research board` builds the board from the registry. The curated part
is the hypothesis, its basis and the derivation for analytical entries,
reviewed like code in `crates/experiment-engine/src/board.rs`. Everything
else is recomputed: evidence, counterexamples, rounds covered, the work
factor at 64 rounds, verification status, cost and the next experiment.

`bmr research evolve [--run N]` generates the next experiments from rules
over the records:
- extend a reduced-round frontier (now: smt at 5, 6, 7 rounds, the gap
  between its 4-round deviation and its clean 8);
- replicate single-seed hypotheses on a new seed;
- escalate full-round candidates (none exist);
- re-measure what a model could not confirm;
- retry solver timeouts with four times the budget (now: trail-sat
  beyond round 5);
- design a first experiment for untested families (now: probabilistic
  neutral bits for B-15, differential-linear for B-17).

A proposal identical to an existing record is dropped, so the loop does
not repeat itself. Negative findings stay in the registry; nothing is
deleted.

## Mission 5: verification

| Claim | Survived |
| --- | --- |
| Atlas statistics | independent SHA-256 recomputation of every statistic over 2^16 nonces at each round count; known block hashes; rehashed hit samples; identical digest in three full executions; 16 templates including 4 real blocks; held-out templates for every strategy |
| Solver characteristics | every round measured on up to 2^33 real transitions; MSB control 2^-10.988 against the exact 2^-11 |
| Identities | z3 proof over all templates plus 4,096 random headers in two other implementations |
| Older kinds | digests identical to the previous final run |

Corrections found while doing this, all before any record was published:

- A normal approximation for tiny expected counts (neighbour pairs, extreme
  Hamming classes) produced false significance (p_family 2e-6 for 7 pairs
  against 1.01 expected; exact Poisson gives 0.13). Classes below 5
  expected hits are now excluded and neighbours use exact Poisson tails.
- The solver's header start counted a W3 difference entering after the
  searched window as nonzero for free, giving weight-0 optima. Both starts
  now end on the same round.
- W0 cannot differ under a fixed midstate (the merkle root's other 28 bytes
  are in block 1). trail-sat excludes it. trail-search-0001 and
  trail-search-0002 carry an erratum: their W0 trails are unreachable for a
  miner, and their conclusion stands.
- The provenance fingerprint did not cover the new modules; fixed in
  `49a3e3c` before the final run.

## Mission 6: unconventional approaches

All of this section is a speculative model [quantum-model-0001], kept apart
from the measurements above.

The Grover oracle is built from the hardware model's exact operator count
for the cheapest datapath:
- 1.47 × 10^5 Toffoli per iteration (1.03 × 10^6 T gates);
- Toffoli depth 4.7 × 10^4;
- about 82,000 logical qubits, a crude count.

At d = 80 target bits and 1 µs per logical Toffoli:
- one machine needs 1,282 years;
- finishing inside 600 s needs 4.5 × 10^15 machines;
- total oracle queries are then 4.8 × 10^-5 of the classical evaluations,
  8.6 × 10^24 Toffoli in all.

The query saving is real in the model. The block interval makes it
irrelevant.

The Landauer bound for the same datapath is 6.0 × 10^-4 J per terahash.
Reversible or specialised circuits can only approach it. They change energy
per hash, never the number of hashes.

## Limits

What this run does not exclude:

- Strategy families outside the ones scored (fixed bits, linear half-spaces
  over two 24-bit projections, byte and Hamming classes, 1,552 neighbour
  relations and their groups, all pairwise differences among higher hits).
  A nonlinear selection rule that is cheap to evaluate is not tested, except
  through its effect on these statistics.
- Effects below the stated sensitivity. The held-out intervals bound a
  usable class strategy's work factor to about 0.996..1.006 (subspaces),
  0.94..1.02 (bytes) and much wider for neighbour relations, whose expected
  counts are about one pair per template.
- Relations outside the solver model (signed, carry-free, at most two digits
  per bit). The model's optima are measured, but characteristics outside it
  are not searched. The time-nonce start ignores the consensus limits on the
  time field, which only makes it more favourable to the miner.
- The literature, which this run does not reproduce. The best published
  attacks reach a practical semi-free-start collision on 39 of 64 steps of
  SHA-256 ([ePrint 2024/349](https://eprint.iacr.org/2024/349)), and
  preimage-type attacks reach 43 to 52 steps with full message freedom and
  close to generic cost ([ePrint 2009/477](https://eprint.iacr.org/2009/477),
  [ePrint 2011/286](https://eprint.iacr.org/2011/286)). A Bitcoin miner
  controls 64 bits of one message block (nonce, time) and none of the outer
  block, and needs all 64 + 64 steps.
- Every hypothesis rests on one run seed. Some kinds use many seeds or
  templates internally; the board proposes reruns on a new seed.
